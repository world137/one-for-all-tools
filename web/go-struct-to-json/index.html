Go Struct → JSON Mock Generator

Paste your Go structs, select the root struct, and generate a Postman-ready JSON request body. Supports structs with or without the `type` keyword, plain Go types (int, string, bool, ...), and null.X wrapper types side by side.
Documentation & Example (V3)

New in V3

  • Root Struct selector — paste multiple structs and choose which one is the root.
  • JSON Pretty button — formats the generated JSON with 4-space indentation.
  • Structs without type — parses both type HelloWorld struct {...} and HelloWorld struct {...}, useful when copying from generated docs or snippets.
  • Plain Go types — native types like int, string, bool, float64, byte, rune are mocked the same way as their null.X equivalents.

Example

Input:

HelloWorld struct {
    Body ExampleBody `json:"example_body"`
}

ExampleBody struct {
    Test         null.Int64  `json:"test"`
    Apple        null.String `json:"apple"`
}
Root StructHelloWorld
Root JSON Keyrq_body

Output:

{
    "rq_body": {
        "example_body": {
            "test": -1,
            "apple": "mock-string"
        }
    }
}

Buttons

  • Generate JSON — generate JSON from the selected root struct.
  • JSON Pretty — format the generated JSON with indentation.
  • Copy JSON — copy JSON to clipboard.
  • Clear — clear the input and output.

Supported

  • Go primitive types: string, bool, int/int8-64, uint/uint8-64, byte, rune, float32/float64
  • json struct tags, nested structs, structs with or without type
  • Pointers, slices, arrays, maps
  • null.Int64, null.Int32, null.String, null.Dec2, null.Date, time.Time
  • Custom mock:"..." values

Custom mock values

Example:

HelloWorld struct {
    Test    string `json:"test" mock:"text"`
    Apple   string `json:"apple" mock:"-200000"`
}

Output:

{
    "test": "text",
    "apple": -200000
}

Important

If two structs have exactly the same name in the pasted input, the later definition replaces the earlier one. In real Go code, duplicate type names are not allowed in the same package. For types with the same name from different packages, package-aware resolution would be needed.
